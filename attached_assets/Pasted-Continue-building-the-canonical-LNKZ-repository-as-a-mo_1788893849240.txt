Continue building the canonical LNKZ repository as a mobile-first application.

First inspect the existing repository before changing anything. LNKZ already contains the relay backend, REST API, MCP surfaces, web console, storage, authentication, and deployment files. Reuse the existing backend contracts. Do not create a duplicate relay, database, MCP server, or incompatible API.

Build an Expo React Native mobile app in a new `apps/mobile` workspace using TypeScript. It should run in Replit with the web preview and remain compatible with Expo Go for device testing.

Product name: LNKZ Mobile.

Primary purpose:
LNKZ moves useful context between conversations, LLMs, apps, devices, and people. The mobile app should let a user capture conversations, search their library, generate context packets, and create secure handoff links.

Use the existing LNKZ REST API through a typed client. Preserve all existing endpoint paths, request formats, response formats, environment variable names, MCP tool names, resource URIs, authentication behavior, and security boundaries.

Build these mobile screens:

1. Welcome / setup
   - Explain what LNKZ does.
   - Configure the LNKZ server URL.
   - Enter an API key.
   - Store credentials only in secure device storage.
   - Never print API keys or handoff tokens in logs.

2. Conversation library
   - Recent conversations.
   - Search field.
   - Filter by provider, tags, and date.
   - Pull to refresh.
   - Empty state with a clear import action.

3. Import conversation
   - Paste transcript text.
   - Support existing LNKZ import formats.
   - Show dry-run preview before saving.
   - Display warnings returned by the backend.
   - Confirm before writing imported data.

4. Conversation detail
   - Title, provider, participants, tags, and timestamps.
   - Message timeline.
   - Decisions, open questions, action items, facts, and topics.
   - Actions for append, export, create handoff, and build context packet.

5. Context packet builder
   - Select one or more conversations.
   - Set a token budget.
   - Toggle external connector search.
   - Show generated Markdown packet.
   - Allow copying and sharing through the operating system share sheet.

6. Handoff screen
   - Set expiration, usage limit, audience, note, and redaction.
   - Show the generated share link once.
   - Make it clear that the link is a bearer secret.
   - Do not store or log the raw token unnecessarily.
   - Show active handoffs and allow revocation.

7. Settings
   - Server URL.
   - Connection test.
   - Credential reset.
   - Theme preference.
   - About screen linking to the LNKZ repository and documentation.

Design direction:
- Mobile-first layout with large touch targets.
- Clean dark interface matching the existing LNKZ visual language.
- Use reusable components, spacing tokens, typography tokens, and accessible color contrast.
- Include loading, error, empty, offline, and retry states.
- Support small phones and tablet widths.
- Avoid decorative complexity; prioritize fast scanning and clear actions.

Backend work:
- Inspect the current REST routes and create or improve only the endpoints needed by the mobile app.
- Keep the existing SQLite/Postgres storage boundary.
- Keep API-key and multi-key authentication intact.
- Keep origin, rate-limit, handoff, audit, and redaction protections intact.
- Add typed request/response models where missing.
- Add health and connection-test support only if it can reuse existing routes safely.
- Do not add model calls. Conversation analysis must remain deterministic.
- Do not expose database credentials, API keys, connector secrets, or raw handoff tokens in logs.

Implementation requirements:
- Add the mobile app to the existing pnpm workspace.
- Add scripts for mobile typechecking, linting, tests, and development.
- Reuse shared types only if doing so does not couple the mobile app to server internals.
- Add a small API client layer with request cancellation, timeout handling, normalized errors, and auth headers.
- Add meaningful tests for authentication handling, import preview, library loading, packet generation, and handoff redaction.
- Do not rewrite the existing web app or backend architecture.
- Do not delete existing files or rename public contracts.

Before finishing:
1. Run the existing root typecheck, tests, and build.
2. Run mobile typecheck, tests, and web preview build.
3. Verify the mobile app against a local LNKZ server using a temporary test database.
4. Check that API keys and handoff tokens never appear in logs or error messages.
5. Document how to run the mobile app in Replit, Expo Go, and the browser preview.
6. Summarize changed files, commands run, known limitations, and the next recommended mobile feature.

Work incrementally. Start by inspecting the current LNKZ structure and API contracts, then scaffold `apps/mobile`, then implement the library and conversation detail flow before adding packet and handoff workflows.
